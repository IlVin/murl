# URL Shortener Service Storage

Высокопроизводительное ядро системы сокращения ссылок, реализованное на языке Go. Архитектура спроектирована с упором на максимальную пропускную способность (throughput) и низкие задержки (latency).

## Архитектура хранилища (Repository)

Система построена на принципах **чистой архитектуры**, где бизнес-логика полностью отделена от физической реализации хранения данных. Это позволяет прозрачно масштабировать сервис и менять тип базы данных без правки основного кода.

### Гибкая система драйверов
Модуль `Repo` спроектирован как универсальный оркестратор, способный работать с любым драйвером, реализующим интерфейс `RepoDrv`.

*   🚀 **InMemory (Текущий)** — Экстремально быстрый драйвер, хранящий данные в оперативной памяти. Оптимизирован для Highload-нагрузок за счет минимизации конкуренции между потоками.
*   🐘 **PostgreSQL (В разработке)** — Драйвер для обеспечения персистентности. Позволяет переключиться на надежное долгосрочное хранение с поддержкой транзакций через изменение одного параметра в конфигурации.

### Ключевые особенности реализации

#### 1. Слой бизнес-логики (`Repo`)
*   **Равномерное распределение:** Использует алгоритм **xxhash** для вычисления номера шарда. Это гарантирует равномерную загрузку всех сегментов памяти и исключает появление «горячих» зон.
*   **Абстракция:** Оркестратор работает через интерфейсы, обеспечивая потокобезопасный доступ к данным без использования глобальных блокировок.

#### 2. Оптимизации InMemory драйвера
*   **Шардирование (Sharding):** Данные разделены на независимые сегменты. Каждая горутина блокирует только один шард, что позволяет системе масштабироваться линейно вместе с ростом количества ядер CPU.
*   **Double-Checked Locking:** Стратегия записи "сначала проверь, потом блокируй": проверка ключа под `RLock` предотвращает лишние эксклюзивные блокировки при повторных запросах.
*   **CPU Cache Alignment (Padding):** Структуры шардов выровнены по **64-байтной кэш-линии**. Это полностью устраняет эффект **False Sharing**, предотвращая взаимное замедление ядер процессора.
*   **Поиск $O(1)$:** Индексация через хеш-таблицы (`map`) обеспечивает мгновенный доступ к данным вне зависимости от объема базы.

### Технологический стек
*   **Go** (1.21+)
*   **xxhash**: Сверхбыстрое некриптографическое хеширование строк.
*   **Uber-go zap**: Структурированное логирование с высокой производительностью.
*   **sync.RWMutex**: Тонкая настройка конкурентного доступа.
