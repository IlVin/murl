# PostgreSQL Repository — Реализация хранилища на базе БД

Пакет `internal/repository/pg` предоставляет реализацию интерфейсов `RepoLinks` и `RepoLinksBySessionID` для работы с базой данных PostgreSQL. Он спроектирован для обеспечения высокой производительности и надежности в многопоточной среде.

## Архитектура и технологии

Реализация опирается на продвинутые возможности адаптера `pgc`:

1.  **Типизированные запросы**: Использование `pgc.Query[T]` и `pgc.Command` позволяет выявлять ошибки структуры данных на этапе компиляции и обеспечивает автоматический нейминг спанов в трейсах.
2.  **Streaming Batching**: Массовые операции (`BatchUpSert`, `BatchDelBySessionID`) реализованы через `PgBatcher`, что превращает запись данных в асинхронный конвейер.
3.  **Оптимизированный UpSert**: Для вставки ссылок используется логика на стороне БД (`INSERT ... ON CONFLICT DO NOTHING` + `SELECT`), что исключает лишние сетевые запросы и обработку исключений `UniqueViolation` в коде.

## Особенности реализации

### 1. Шардирование и ссылки
Несмотря на то, что данные хранятся в одной БД, репозиторий соблюдает логику шардирования приложения:
*   При записи вычисляется `ShardID` на основе URL или сессии.
*   Короткие ссылки формируются с учетом этого идентификатора, что позволяет в будущем легко мигрировать на распределенную БД без изменения формата ссылок.

### 2. Мягкое удаление (Soft Delete)
Удаление ссылок пользователями реализовано через установку флага `deleted = true`. 
*   **Select**: При получении ссылки метод `Select` возвращает статус `deleted`.
*   **Batch Delete**: Выполняется асинхронно. Метод `BatchDelBySessionID` инициирует фоновый процесс удаления, используя `context.WithoutCancel`, что гарантирует завершение операции даже если пользователь прервал HTTP-соединение.

### 3. Гарантии целостности
Все запросы изменения данных (`AsWrite`) направляются на Master-узел через `CQRSConnector`, гарантируя, что пользователь сразу увидит результат своего действия (Read-After-Write consistency).

## Примеры SQL-логики

```sql
-- Пример атомарного UpSert с возвратом флага конфликта
WITH ins AS (
    INSERT INTO murl (url) VALUES ($1)
    ON CONFLICT (url) DO NOTHING RETURNING id
)
SELECT id, 'f'::boolean FROM ins
UNION ALL
SELECT id, 't'::boolean FROM murl WHERE url = $1
LIMIT 1;
```

## Использование

Репозиторий инициализируется внутри `repo.NewRepo` при выборе драйвера `PgDB`:

```go
inst, _ := pgc.NewPgConnector(ctx, dsn)
linksRepo := pg.NewPgRepoLinks(inst)

// Анонимная вставка
path, conflict, err := linksRepo.UpSert(ctx, "https://example.com")
```

```Документация:``` Подробное описание SQL-манифестов и логики батчинга доступно через `godoc -http=:6060` в разделе `internal/repository/pg`.
