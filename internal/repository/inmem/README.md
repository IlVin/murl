# Module: In-Memory Repository (inmem)

Пакет `inmem` предоставляет высокопроизводительную потокобезопасную реализацию интерфейса `repository.RepoLinks`. Данные хранятся в оперативной памяти с использованием сегментированных блокировок (шардирования) для минимизации задержек и исключения конкуренции за ресурсы (Lock Contention).

---

## Архитектура и компоненты

### 1. InMemCore (`core.go`)
Ядро хранилища, отвечающее за физическое разделение данных на независимые сегменты (**shards**).

*   **False Sharing Protection**: Использование `cpu.CacheLinePad` гарантирует, что мьютексы разных шардов не попадут в одну кэш-линию процессора, что критично для производительности на многоядерных системах.
*   **Segmented Locking**: Каждый шард обладает собственным `sync.RWMutex`.
*   **Zero-Copy Safety**: Поле `_ sync.Locker` предотвращает случайное копирование структур шардов (детектируется через `go vet`).

### 2. InMemRepoLinks (`repo_links_impl.go`)
Реализация бизнес-логики репозитория.

*   **Double-Checked Locking**: В методе `UpSert` сначала выполняется чтение под `RLock`, и только при отсутствии данных запрашивается эксклюзивная `Lock`. Это позволяет множеству потоков одновременно проверять наличие одних и тех же URL без блокировки всей системы.
*   **Двусторонний индекс**:
    *   `Data [uint64]string`: Быстрый поиск Long URL по индексу.
    *   `Index [string]uint64`: Реверсивный индекс для мгновенной проверки дубликатов URL и реализации логики `ConflictFlag`.

## Использование

### Инициализация
Для создания репозитория необходимо передать объект конфигурации, реализующий интерфейс `InMemConfig`.

```go
type Config struct {
    size byte
}
func (c *Config) ShardSize() byte { return c.size }

// ...

core, _ := inmem.NewInMemCore(&Config{size: 64})
repo := inmem.NewInMemRepoLinks(core)
```

### Основные операции

```go
// 1. Сохранение URL (автоматическая генерация пути)
short, conflict, err := repo.UpSert(ctx, "https://example.com")

// 2. Поиск по короткому пути
long, err := repo.Select(ctx, short)

// 3. Пакетная обработка
result, err := repo.BatchUpSert(ctx, myBatchPayload)
```

## Технические детали

### Формат данных
Репозиторий тесно интегрирован с модулем `model`. Для генерации путей используются методы `MakeShortPath` и `ParseShortPath`, которые кодируют `ShardID` и `Index` в компактную Base64 строку.

### Метод Set
Метод `Set` предназначен для принудительной синхронизации данных. Он:
1. Удаляет старые ассоциации, если ID или URL уже заняты.
2. Гарантирует, что внутренний счетчик `LastIdx` шарда не окажется позади установленного вручную индекса, предотвращая будущие коллизии.

### Пакетная вставка (Batch)
Метод `BatchUpSert` итерируется по элементам пакета и выполняет атомарные `UpSert`. В случае отмены контекста (например, по таймауту HTTP-запроса) выполнение прерывается, возвращая уже обработанную часть данных.

---

## Производительность
*   **Сложность операций**: O(1) для всех основных методов.
*   **Аллокации**: Минимизированы за счет использования `defaultCap` (300 элементов на шард по умолчанию).
*   **Масштабируемость**: Линейная зависимость от количества шардов. Рекомендуется устанавливать `ShardSize` равным степени двойки (например, 16, 32, 64).
