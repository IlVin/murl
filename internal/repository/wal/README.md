# Write-Ahead Log (WAL) — Журнал опережающей записи

Пакет `internal/repository/wal` реализует механизм персистентного хранения потока событий. Он позволяет восстановить состояние **InMemory** хранилища до актуального момента после перезапуска или сбоя приложения.

## Принцип работы

Система следует классической схеме **Append-Only Log**:
1.  Каждое изменение данных (событие) сначала сериализуется в JSON.
2.  Событие записывается в конец файла лога.
3.  Выполняется принудительный сброс данных на диск (`fsync`).
4.  Только после успешной записи на диск операция считается завершенной.

## Ключевые возможности

### 1. Гарантированная сохранность
Метод `Push` вызывает `Sync()` после каждой записи. Это гарантирует, что даже при внезапном отключении питания данные, подтвержденные пользователю, останутся в файле.

### 2. Потоковое восстановление (Replay)
Функция `LoadWAL` позволяет эффективно прочитать журнал при старте системы:
*   **Ленивое чтение**: События читаются построчно через `bufio.Reader`, не загружая весь лог в память.
*   **Асинхронность**: События передаются через канал, что позволяет репозиторию применять их параллельно с процессом чтения с диска.
*   **Отказоустойчивость**: Если одна строка в логе повреждена, система логирует ошибку и продолжает чтение следующего события.

### 3. Формат данных
Журнал хранит события в формате **JSON Lines** (одно событие — одна строка). Это делает лог читаемым для человека и упрощает интеграцию с внешними системами обработки логов (например, ELK или ClickHouse).

## Использование

### Запись событий
```go
log, _ := wal.NewWAL("/path/to/storage.wal")
defer log.Close()

// Любое событие из internal/model/event
err := log.Push(myEvent)
```

### Восстановление состояния
```go
ctx := context.Background()
ch, err := wal.LoadWAL(ctx, "/path/to/storage.wal")

for ev := range ch {
    // Применяем событие к репозиторию
    repo.On(ctx, ev)
}
```
