# Module: Postgres Cluster Implementation (pgcluster)

Пакет `pgcluster` содержит конкретную реализацию интерфейса `pgc.PgCluster`. Он управляет жизненным циклом физических соединений с PostgreSQL и распределяет логические шарды по доступным инстансам.

---

## Архитектура реализации

На текущем этапе развития системы реализована схема **"Много к Одному"**:
*   Система оперирует множеством логических шардов (определяется параметром `ShardSize`).
*   Все логические шарды терминируются на одном физическом инстансе `PgInstance`.
*   Архитектура позволяет бесшовно перейти к горизонтальному масштабированию (разделению на разные физические сервера) без изменения кода репозиториев.

---

## Основные функции

### 1. Конструктор (NewPgCluster)
Инициализирует пул соединений и распределяет его по внутренней таблице шардов.

```go
cfg := &MyConfig{size: 64, dsn: "postgres://..."}
m, _ := metrics.NewPgMetrics(reg)

// Возвращает интерфейс pgc.PgCluster
cluster, err := pgcluster.NewPgCluster(ctx, cfg, m)
```

### 2. Оркестрация миграций
Метод `RunMigrations` гарантирует, что миграции будут запущены ровно один раз для каждого уникального физического инстанса, независимо от количества логических шардов, указывающих на него.

### 3. Управление состоянием (Ping / Close)
*   **Ping**: Последовательно проверяет доступность всех физических узлов.
*   **Close**: Гарантирует корректное закрытие всех пулов соединений при остановке приложения. Если при инициализации части кластера произошла ошибка, конструктор сам вызовет `Close` для уже созданных объектов.

---

## Технические особенности

*   **ShardID**: Использует универсальную функцию хеширования из `internal/model`, обеспечивая консистентность данных между кешем (In-Memory) и основной БД.
*   **GetShard**: Выполняет мгновенный поиск (O(1)) нужного инстанса в слайсе шардов.
*   **Изоляция**: Реализация `pgCluster` скрыта (unexported), взаимодействие происходит только через интерфейс `pgc.PgCluster`.

---

## Логирование

Модуль использует структурированное логирование `slog` для фиксации важных событий:
*   Инициализация кластера с указанием количества шардов и уникальных инстансов.
*   Старт и результат выполнения миграций для каждого узла.
*   Ошибки доступа к шардам.
