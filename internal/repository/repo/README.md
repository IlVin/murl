# Repo Implementation — Фасад системы хранения

Пакет `internal/repository/repo` реализует центральный фасад хранилища. Он объединяет низкоуровневые репозитории (`InMemory`, `PostgreSQL`), систему логирования событий (`WAL`) и обеспечивает прозрачный интерфейс для бизнес-логики.

## Архитектура и компоненты

Модуль работает по принципу оркестратора, делегируя выполнение операций специализированным подсистемам:

*   **Драйверы**: Поддержка `InMemory` (для скорости) и `PgDB` (для надежности).
*   **WAL (Write-Ahead Log)**: Гарантирует сохранность данных даже в режиме работы через оперативную память.
*   **Event Replay**: При старте система автоматически вычитывает журнал событий и восстанавливает состояние через метод `On`.

## Логика работы

### 1. Инициализация (NewRepo)
При создании репозиторий:
1. Выбирает реализацию согласно `cfg.RepoDrv()`.
2. Если используется **Postgres**, автоматически запускает миграции схемы БД.
3. Если указан `EventStoragePath`, загружает и «проигрывает» все события из файла для восстановления состояния в памяти.

### 2. Запись данных и WAL
Каждая операция изменения данных (`AddURL`, `Batch`, `Delete`) проходит через цепочку:
*   Выполнение в основном хранилище (БД или Память).
*   Если операция успешна и **не является дубликатом** (`ConflictFlag == false`), она упаковывается в `event.Event`.
*   Событие записывается в `wal` с принудительным сбросом на диск (`fsync`).

### 3. Восстановление (Method On)
Метод `On` реализует логику **Event Sourcing**. Он принимает сохраненные события и повторно применяет их к хранилищу. Это позволяет использовать быстрый `InMemory` репозиторий без риска потери данных при перезагрузке.

## Особенности реализации

*   **Изоляция чтения**: События чтения (`GetURL`) не записываются в WAL и не обрабатываются методом `On`, так как они не изменяют состояние системы.
*   **Дедупликация в логах**: Конфликтные ситуации (попытка сократить уже существующий URL) обрабатываются хранилищем, но не попадают в журнал событий, что экономит место на диске.

## Примеры использования

```go
// Создание универсального репозитория через конфиг
db, err := repo.NewRepo(ctx, cfg)
if err != nil {
    log.Fatal(err)
}
defer db.Close(ctx)

// Прозрачная работа с данными
res, err := db.AddURL(ctx, dto.AddURL{OriginalURL: "https://example.com"})
```
