# Модуль Event Model (REST-архитектура на Go)

## Обзор
Модуль предоставляет высокоуровневую, потокобезопасную реализацию системы событий для распределенных приложений. Архитектура построена на принципах **Representational State Transfer (REST)**, где каждое событие является самодостаточным носителем состояния (ресурса) и контекста.

## Ключевые возможности
*   **Инкапсуляция**: Реализация события (`pvtEvent`) полностью скрыта. Работа ведется через интерфейс `Event`.
*   **Строгая типизация**: Использование Generics (`NewEvent[T]`) обеспечивает проверку типов на этапе компиляции.
*   **Потокобезопасность**: Полная защита данных с помощью `sync.RWMutex`, оптимизированная для частого чтения.
*   **Lazy Unmarshaling**: Использование `json.RawMessage` позволяет обрабатывать метаданные событий без затрат на полную десериализацию полезной нагрузки.

## Обоснование проектных решений

### 1. Конструктор `Parse`
Для десериализации событий используется функциональный конструктор `Parse`. Это гарантирует получение полностью инициализированного, валидного объекта, реализующего интерфейс `Event`, либо ошибку. Это исключает нахождение в системе "полупустых" структур.

### 2. Двусторонний маппинг типов (Reflect)
Связь между константами протокола (`EvType`) и структурами данных Go реализована через симметричные функции `getEvTypeByReflect` и `getReflectByEvType`. Это создает единую точку истины для всей системы событий и упрощает добавление новых типов.

### 3. Оптимизация критических секций
В методе `SetPayload` операция `json.Marshal` вынесена за пределы мьютекса. Блокировка захватывается только в момент непосредственного обновления байтового среза в памяти, что минимизирует задержки в высоконагруженных горутинах.

### 4. Валидация при записи
Метод `SetPayload` выполняет динамическую проверку типов. Если попытаться записать структуру, не соответствующую типу события, метод вернет `ErrEvNotCompPayloadType`, предотвращая повреждение данных.

## Спецификация интерфейса Event

Интерфейс `Event` определяет контракт для работы с событиями в системе:

| Метод | Описание |
|:---|:---|
| `GetID() uuid.UUID` | Возвращает уникальный идентификатор события (UUID v4). |
| `GetType() EvType` | Возвращает тип события для определения контекста обработки. |
| `Serialize() ([]byte, error)` | Сериализует все событие (ID, Type, Payload) в формат JSON. |
| `SetPayload(src any) error` | Проверяет тип и сохраняет полезную нагрузку в событие. |
| `GetPayload(dest any) error` | Распаковывает данные из события в целевую структуру. |

**Конструкторы:**
*   `NewEvent[T]()`: Создает новое событие с автоматической генерацией ID и типизированным Payload.
*   `Parse([]byte)`: Восстанавливает событие из входящего потока данных.

## Примеры использования

### Создание и отправка события (Outbound)
```go
// Создаем событие для добавления URL
// p автоматически получает тип *PayloadAddURL
event, p, err := model.NewEvent[model.PayloadAddURL]()
if err != nil {
    log.Fatal(err)
}

p.URL = "https://example.com"
p.ShardID = 1

// Фиксируем состояние и сериализуем
event.SetPayload(p)
data, _ := event.Serialize()

// Восстанавливаем интерфейс из байт
event, err := model.Parse(data)
if err != nil {
    log.Fatal(err)
}

// Обработка на основе типа
switch event.GetType() {
case model.EvAddURL:
    var p model.PayloadAddURL{}
    if err := event.GetPayload(&p); err == nil {
        fmt.Println("Обработка URL:", p.URL)
    }
}
