# Domain Layer — Ядро бизнес-логики

Пакет `internal/domain` содержит основные сущности, типы данных и интерфейсы, которые определяют логику работы приложения `murl`. Согласно принципам Clean Architecture, этот слой является абсолютно независимым: он не импортирует пакеты из слоев `adapters`, `config` или `app`.

## Основные сущности

### Notification
`internal/domain/notification.go` — базовая структура для системы уведомлений и аудита.
*   **Универсальность**: Поле `Message` представлено в виде `[]byte`, что позволяет передавать любые форматы данных (JSON, XML, Protobuf) без изменения доменной модели.
*   **Назначение**: Служит единым стандартом данных для всех адаптеров аудита (файловых, сетевых и т.д.).

## Принципы проектирования

1.  **Чистота (Pure Domain)**: Здесь нет логики работы с HTTP, SQL или файловой системой. Только структуры и методы обработки данных.
2.  **Независимость от инфраструктуры**: Если мы решим заменить PostgreSQL на MongoDB или `slog` на `zerolog`, код в этом пакете останется неизменным.
3.  **Единый язык (Ubiquitous Language)**: Имена типов и полей должны соответствовать терминам, используемым в предметной области сокращения ссылок и аудита событий.

## Использование

Объекты из этого слоя создаются в бизнес-логике (Use Cases) и передаются в адаптеры для сохранения или отправки.

```go
import "murl/internal/domain"

// Создание доменного события
notif := domain.Notification{
    Message: []byte(`{"event":"user_signup","id":42}`),
}
```

---
```Документация:``` Полное описание методов и типов доступно через `godoc -http=:6060` в разделе `internal/domain`.
