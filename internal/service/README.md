# Service Layer — Оркестрация бизнес-логики

Пакет `internal/service` реализует основные сценарии использования (Use Cases) приложения `murl`. Он отвечает за координацию работы между хранилищем, системой аудита и правилами валидации данных.

## Основные функции

1.  **Управление ссылками**: Создание (анонимное и авторизованное), получение оригинальных адресов и массовое удаление.
2.  **Валидация и нормализация**: Проверка корректности входящих URL, разбор схем (HTTP/HTTPS) и защита от циклов (блокировка сокращения ссылок на собственный домен).
3.  **Формирование ShortURL**: Преобразование внутренних путей хранилища (`ShortPath`) в полноценные публичные ссылки на основе конфигурации `ShortBaseURL`.
4.  **Интеграция с аудитом**: Асинхронная отправка уведомлений о каждом создании ссылки (`shorten`) и переходе по ней (`follow`).

## Архитектура и зависимости

Сервис спроектирован по принципу инверсии зависимостей (DIP) и взаимодействует с другими слоями через интерфейсы:

*   **ServiceConfig**: Позволяет динамически получать настройки сессий и базовых URL.
*   **Repo**: Универсальный интерфейс хранилища (скрывает детали реализации: Postgres или InMemory).
*   **AuditlogNotifier**: Интерфейс для безопасной асинхронной отправки событий аналитики.

## Обработка ошибок

Сервис нормализует технические ошибки инфраструктуры в семантические бизнес-ошибки:
*   `ErrConflict`: URL уже сокращен (используется для возврата HTTP 409).
*   `ErrGone`: Ссылка удалена владельцем (используется для возврата HTTP 410).
*   `ErrInvalidURLFormat`: Ошибка парсинга или недопустимый протокол.
*   `ErrDomainIsBlocked`: Защита от рекурсивных сокращений.

## Примеры использования

### Создание сервиса
```go
// Все зависимости передаются в виде интерфейсов
svc := service.NewService(ctx, cfg, repository, auditlog)
```

### Сокращение ссылки
```go
// Сервис сам определит, есть ли сессия в контексте, и выполнит аудит
shortURL, err := svc.AddURL(ctx, "https://google.com")
if errors.Is(err, service.ErrConflict) {
    // Обработка случая, когда ссылка уже существует
}
```

## Тестирование
Пакет полностью покрыт Unit-тестами с использованием моков (`MockRepo`, `MockAuditlogNotifier`). Тесты проверяют как успешные сценарии, так и граничные случаи (некорректные протоколы, отмена контекста, конфликты в БД).
