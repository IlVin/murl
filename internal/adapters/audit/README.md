# Audit Adapters — Адаптеры системы аудита и нотификаций

Пакет `internal/adapters/audit` предоставляет реализации потребителей (consumers) для системы логирования событий и уведомлений, поддерживающий вывод в локальные файлы и внешние HTTP-сервисы.

## Архитектура и принципы работы

Основная задача адаптеров — гарантированная доставка сообщений. В отличие от стандартных компонентов системы, адаптеры аудита используют специфические стратегии обработки контекста и блокировок для предотвращения потери данных.

### 1. Файловый аудит (FileAuditlog)
Реализует атомарную запись в локальный файл с использованием блокировок уровня операционной системы.

*   **Надежность**: Используется `syscall.Flock` (эксклюзивная блокировка). Это позволяет нескольким инстансам приложения безопасно писать в один и тот же файл без перемешивания строк.
*   **Гарантия записи**: После каждой операции вызывается `fh.Sync()`, что принудительно сбрасывает кэш ОС на физический диск.
*   **Производительность**: Метод является синхронным и "тяжелым", так как приоритет отдан сохранности данных, а не скорости.

### 2. Сетевой аудит (URLAuditlog)
Обеспечивает отправку нотификаций через HTTP POST во внешние системы (например, Accrual или внешние логгеры).

*   **Игнорирование контекста**: HTTP-запросы внутри адаптера **не используют** проброшенный `context.Context` для прерывания запроса. Это сделано для того, чтобы при завершении работы программы запрос не обрывался "на полуслове", нарушая формат JSON.
*   **Таймауты**: Вместо контекста клиент полагается на внутренний `Timeout` (по умолчанию 10 секунд).
*   **Graceful Shutdown**: Безопасность при выключении системы обеспечивается тем, что вызывающий код (Observer/Worker) дожидается завершения работы всех активных адаптеров перед выходом.

## Инициализация потребителей

Для автоматической регистрации всех активных способов аудита на основе конфигурации используется функция `AddAuditConsumers`.

```go
// Пример автоматической регистрации
audit.AddAuditConsumers(config, observer)
```

## Описание компонентов

### Реестр потребителей
*   `AuditFileID` — константа идентификатора файлового лога.
*   `AuditURLID` — константа идентификатора сетевого лога.

### Интерфейсы
*   `AuditlogConfig` — требования к объекту конфигурации (путь к файлу, URL).
*   `AuditlogSubscriber` — интерфейс реестра для регистрации подписчиков.

## Примеры использования

### Запись в файл
```go
auditor := audit.NewFileAuditlog("audit-01", "/var/log/app/audit.log")
err := auditor.Update(domain.Notification{Message: []byte("event data")})
```

### Отправка по HTTP
```go
auditor := audit.NewURLAuditlog("audit-http", "https://logs.local")
err := auditor.Update(domain.Notification{Message: []byte(`{"status":"ok"}`)})
```

---
```Утилита godoc:``` подробные примеры использования каждой функции доступны через `godoc -http=:6060` в разделе данного пакета.
