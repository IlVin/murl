# PGC (Postgres Connector) — Продвинутый драйвер с поддержкой CQRS, батчинга и OTel

Пакет `internal/adapters/pgc` предоставляет высокоуровневую абстракцию над `pgx/v5`, оптимизированную для работы в высоконагруженных системах с использованием современных возможностей Go 1.23.

## Архитектурная схема компонентов

Система построена по принципу декоратора. Каждый слой добавляет свою логику (отказоустойчивость, роутинг, накопление), сохраняя совместимость с интерфейсом `PgInstance`.

```text
[   PgBatcher[T, C]  ]  <-- Типизированный конвейер, Backpressure, Ретраи
           |
           v
[    CQRSConnector   ]  <-- Роутинг Read/Write + Ретраи на реплики
           |
           v
[     PgConnector    ]  <-- Базовый узел (Pool + Circuit Breaker + Метрики)
```

## Ключевые возможности

### 1. Современные итераторы (Go 1.23+)
Функции `Fetch` и `SendBatch` возвращают `iter.Seq2[T, error]`, что позволяет обходить результаты запросов в стандартном цикле `for...range`. Это избавляет от ручного управления жизненным циклом строк (`rows.Close`) и делает код чище.

### 2. Умный CQRS и ретраи
`CQRSConnector` автоматически разделяет нагрузку:
*   `ReadOnly` запросы распределяются между доступными репликами по принципу Round-Robin.
*   При сетевых сбоях выполняется прозрачный ретрай на другой узел кластера (если итерация еще не началась).
*   Запросы на запись всегда направляются на Master.

### 3. Потоковый батчер (PgBatcher)
Предназначен для массовых операций с автоматическим управлением:
*   **Буферизация**: Накопление пакетов по количеству или таймауту (`flushInterval`).
*   **Backpressure**: Ограничение входящего потока через емкость каналов.
*   **Retry Logic**: Автоматический повтор попыток выполнения пакета при повторяемых ошибках БД.
*   **Два режима**: Поддержка синхронного ожидания результатов и асинхронного режима "fire-and-forget" (для `NewCommand`).

### 4. Типизация и безопасность: Query[T] и Binder
Файл: `pg_query.go`

`Query[T]` — это статический манифест запроса, который переносит проверку типов со стадии выполнения на стадию компиляции.
- **Автоматический нейминг**: При создании запрос вычисляет свое имя (например, `User (repo/user.go:42)`) через `runtime.Caller`.
- **Binder**: Вместо медленной рефлексии используется типизированная функция-замыкание, возвращающая слайс указателей на поля.
- **Fluent API**: Методы `.AsRead()` и `.AsWrite()` управляют поведением запроса в CQRS-кластере.

### 5. Наблюдаемость (Observability)
Из коробки поддерживается полная интеграция с OpenTelemetry:
*   **Traces**: Трейсинг каждого запроса, включая попытки ретраев и информацию о конкретном узле БД.
*   **Metrics**: Счётчики ретраев, ошибок и гистограммы длительности операций.
*   **Logs**: Интеграция с `slog`, включая автоматическое логирование ошибок асинхронных батчей.

## Примеры использования

### Создание типизированного запроса
```go
type User struct { ID int; Name string }

// Описываем маппинг полей вручную для скорости и типобезопасности
var userQuery = pgc.NewQuery("SELECT id, name FROM users WHERE id = $1", func(u *User) []any {
    return []any{&u.ID, &u.Name}
}).AsRead()
```

### Выполнение в CQRS кластере
```go
// Запрос пойдет на реплику, при сбое — на мастер или другую реплику
user, err := pgc.FetchRow(ctx, cqrs, userQuery, 123)
```

### Пакетная обработка (Streaming Batch)
```go
batcher := pgc.NewPgBatcher[string](ctx, db, insertLog)

// Отправляем данные в отдельной горутине
go func() {
    defer batcher.Close()
    batcher.Requests() <- pgc.BatchEntry[string]{Args: []any{"data"}, Ctx: "ID-1"}
}()

// Читаем результаты в основном потоке
for res := range batcher.Results() {
    if res.Err != nil {
        slog.Error("fail", "id", res.Ctx, "err", res.Err)
    }
}
```

## Преимущества и недостатки решений



| Решение | Преимущества | Недостатки |
| :--- | :--- | :--- |
| **Query[T]** | Типобезопасность, авто-нейминг для OTel. | Требует написания Binder функции. |
| **CQRSConnector** | Прозрачные ретраи, балансировка реплик. | Сложнее отладка цепочки вызовов. |
| **PgBatcher** | Огромная экономия сетевых ресурсов. | Асинхронная природа обработки ошибок. |
