# PGC (Postgres Connector) — Продвинутый драйвер с поддержкой шардирования, CQRS и OTel

Пакет `internal/adapters/pgc` — это высокоуровневая абстракция над `pgx/v5`, предназначенная для построения типизированных, отказоустойчивых распределенных систем. 

## Архитектурная схема компонентов

Система построена по принципу декоратора ("Матрешки"). Каждый слой добавляет свою логику, сохраняя совместимость с базовым интерфейсом.

```text
[ PgClusterBatcher ]  <-- Оркестратор батчей по всему кластеру шардов

       |
       v
[   PgBatcher[T]   ]  <-- Буферизация, Backpressure, Ретраи батча
       |
       v
[     PgCluster    ]  <-- Логическое шардирование (Proxy Layer)

       |
       v
[   CQRSConnector  ]  <-- Роутинг Read/Write + Ретраи на реплики
       |
       v
[    PgConnector   ]  <-- Базовый узел (Pool + Circuit Breaker + Метрики)
```

## Типизация данных: Query[T] и Binder
Файл: `pg_query.go`

`Query[T]` — это статический манифест запроса, который переносит проверку типов со стадии выполнения на стадию компиляции. Благодаря дженерикам мы гарантируем, что структура, в которую сканируются данные, всегда соответствует ожидаемой.

### Блок-схема работы Query[T]:

```text
[ Инициализация NewQuery[T] ] 

          |
          v
[ Определение Binder[T] ] -- (Указывает, какие поля структуры T мапить)
          |
          v
[ Исполнение Fetch/Exec ] -- (Использует NewTarget() для создания T)

          |
          v
[ Scan в поля структуры ] -- (Типобезопасно через []any)
```

**Ключевые особенности Query[T]:**
- **Автоматический нейминг**: При создании запрос сам вычисляет свое имя (например, `User (repo/user.go:42)`). Это имя используется в трейсах OTel.
- **Binder**: Вместо медленной рефлексии при каждом запросе используется типизированная функция маппинга, возвращающая слайс указателей на поля.
- **Fluent API**: Методы `.AsRead()` и `.AsWrite()` управляют поведением запроса в CQRS-кластере.

## Описание модулей

### 1. Базовый уровень: PgConnector
Файл: `pg_connector.go`
- **Circuit Breaker**: Если база падает (3 ошибки подряд), коннектор "размыкается" и мгновенно возвращает ошибку, не нагружая мертвую систему.
- **Метрики**: Пишет `db.client.operation.duration` для Prometheus.

### 2. Топология: CQRSConnector
Файл: `cqrs_connector.go`
- **Smart Retry**: Если реплика вернула сетевую ошибку, коннектор прозрачно для пользователя переключается на следующую живую ноду.
- **Безопасность**: Ретрай запрещен, если данные уже начали передаваться в `yield`, чтобы избежать дубликатов.

### 3. Масштабирование: PgCluster
Файл: `pg_cluster.go`
- **Shard Proxy**: Каждый шард оборачивается в прокси, добавляющий в трейсы атрибуты `db.pgc.shard_id`.
- **Дедупликация**: Миграции и Close() выполняются только на уникальных физических хостах.

### 4. Производительность: Batching
Файлы: `pg_batcher.go`, `pg_cluster_batcher.go`
- **Backpressure**: Система блокирует `Push`, если потребитель не успевает вычитывать данные, защищая сервис от OOM.
- **Fan-In**: Кластерный батчер собирает результаты со всех шардов параллельно, выдавая их в один итератор.

## Примеры использования

### Создание типизированного запроса
```go
type User struct { ID int; Name string }

// Описываем маппинг полей вручную для скорости и типобезопасности
var userQuery = pgc.NewQuery("SELECT id, name FROM users WHERE id = $1", func(u *User) []any {
    return []any{&u.ID, &u.Name}
}).AsRead()
```

### Выполнение в CQRS кластере
```go
// Запрос пойдет на реплику, при сбое — на мастер или другую реплику
user, err := pgc.FetchRow(ctx, cqrs, userQuery, 123)
```

### Кластерный батчинг (Fan-In)
```go
cb := pgc.NewPgClusterBatcher(ctx, cluster, otel, userQuery)

// Пушим в разные шарды
_ = cb.Push(userId1, userId1)
_ = cb.Push(userId2, userId2)

// Собираем всё в одном цикле
for res, err := range cb.All() {
    fmt.Printf("User found: %s\n", res.Name)
}
```

## Телеметрия (OpenTelemetry)

Благодаря вложенности прокси-объектов, вы получаете детализированную иерархию спанов.

**Пример иерархии в трейсе:**
1. `User.Get` (Слой Shard: `db.pgc.shard_id=1`)
2.   └── `User.Get` (Слой CQRS: попытка на Replica-1)
3.     └── `User.Get` (Слой Connector: `server.address=10.0.0.5`, `db.query.text=SELECT...`)

**Кастомные атрибуты (`db.pgc.*`):**
- `db.pgc.shard_id`: ID шарда.
- `db.pgc.is_readonly`: Тип запроса.
- `db.pgc.batch_size`: Размер пачки.

## Преимущества и недостатки решений

| Решение | Преимущества | Недостатки |
| :--- | :--- | :--- |
| **Query[T]** | Типобезопасность, авто-нейминг. | Требует написания Binder функции. |
| **CQRSConnector** | Ретраи, распределение нагрузки. | Сложнее конфигурация. |
| **PgCluster** | Горизонтальное масштабирование. | Нужно управлять ключами шардирования. |
| **Batching** | Экономия сетевых ресурсов. | Усложнение обработки ошибок. |
