# Adapters Layer — Инфраструктурные адаптеры

Пакет `internal/adapters` содержит реализации интерфейсов, определенных в слое Core/Domain. Это "внешнее кольцо" архитектуры, которое отвечает за преобразование данных из удобного для приложения формата в формат, специфичный для внешних сервисов и хранилищ.

## Структура пакета

### 1. PostgreSQL (pgc)
`internal/adapters/pgc` — высокоуровневый драйвер для работы с БД.
* **CQRS**: Прозрачное разделение потоков чтения и записи.
* **Streaming Batching**: Эффективная вставка и обновление данных через итераторы Go 1.23.
* **Observability**: Глубокая интеграция с OpenTelemetry (трейсы и метрики на уровне каждого запроса).

### 2. Audit & Notifications (audit)
`internal/adapters/audit` — реализация системы логирования и нотификаций.
* **File Audit**: Надежная запись в файлы с использованием блокировок ОС (`flock`).
* **URL Audit**: Отправка уведомлений по HTTP с гарантией целостности JSON (игнорирование прерывания контекста).
* **Observer Pattern**: Удобная регистрация потребителей через `AuditlogSubscriber`.

## Принципы разработки адаптеров

1. **Изоляция**: Весь специфичный код (SQL-запросы, HTTP-заголовки, работа с дескрипторами файлов) скрыт внутри адаптера.
2. **Типобезопасность**: Использование дженериков для маппинга данных из инфраструктуры в доменные модели.
3. **Отказоустойчивость**:
    * Использование `Circuit Breaker` для предотвращения каскадных сбоев.
    * Стратегии автоматических повторов (`Retry Logic`) для сетевых операций.
4. **Graceful Shutdown**: Все адаптеры обязаны поддерживать корректное завершение работы без потери данных (сброс буферов, закрытие соединений).

## Использование в приложении

Адаптеры инициализируются на уровне `main.go` (Composition Root) и передаются в Use Cases в виде интерфейсов.

```go
// Пример инициализации
db := pgc.NewCQRSConnector(masterPool, replicas...)
auditor := audit.NewFileAuditlog("main", "/var/log/audit.log")

// Передача в сервис (Domain/Use Case)
service := orders.NewService(db, auditor)
```
