# HTTP Handlers — Транспортный слой

Пакет `internal/handlers` реализует набор HTTP-обработчиков для сервиса сокращения ссылок. Он отвечает за прием запросов, валидацию форматов данных (JSON/Text), управление сессиями и формирование ответов согласно протоколу HTTP.

## Архитектура и принципы

### 1. Изоляция бизнес-логики
Хендлеры не содержат бизнес-правил. Они взаимодействуют с приложением через интерфейс `MicroURLService`. Это позволяет легко тестировать транспортный слой отдельно от базы данных и менять реализацию сервиса без правки HTTP-кода.

### 2. Потоковая обработка (Streaming)
Для работы с большими объемами данных в методе `APIShortenBatch` используется библиотека `jstream`.
*   **Memory Efficiency**: JSON-массивы не загружаются в память целиком. Элементы читаются и обрабатываются итеративно.
*   **Chunked Response**: Результаты записываются в ответ по мере готовности, что снижает потребление ОЗУ и ускоряет получение первых данных клиентом.

### 3. Обработка ошибок
Централизованная функция `ErrHandling` транслирует внутренние ошибки сервиса в стандартные HTTP-статусы:
*   `400 Bad Request` — неверный формат URL или пустой запрос.
*   `401 Unauthorized` — отсутствие активной сессии для защищенных методов.
*   `409 Conflict` — попытка создать ссылку, которая уже существует.
*   `410 Gone` — переход по ссылке, которая была удалена владельцем.
*   `422 Unprocessable Entity` — блокировка рекурсивных сокращений.

## Основные эндпоинты


| Метод | Путь | Описание | Формат |
| :--- | :--- | :--- | :--- |
| `POST` | `/` | Быстрое сокращение ссылки | Plain Text |
| `POST` | `/api/shorten` | Сокращение через JSON API | JSON |
| `POST` | `/api/shorten/batch`| Массовое сокращение | Streaming JSON |
| `GET` | `/{id}` | Редирект на оригинал | Redirect 307 |
| `GET` | `/api/user/urls` | Список ссылок пользователя | JSON (Auth required) |
| `DELETE`| `/api/user/urls` | Удаление ссылок | JSON (Auth required) |
| `GET` | `/ping` | Проверка доступности БД | — |

## Работа с сессиями

Хендлеры управления историей (`APIUserURLs`, `DeleteAPIUserURLs`) используют механизм авторизации на базе сессий. Информация о пользователе извлекается из контекста запроса, куда она помещается предварительно настроенной Middleware.

## Примеры использования

### Инициализация
```go
// Передаем зависимости через интерфейсы
h := handlers.NewHandlers(cfg, microURLService)

// Регистрация в роутере
router.Post("/", h.AddURL())
router.Get("/{id}", h.GetURL())
```

---
```Документация:``` Полный список методов и структур запросов/ответов доступен через `godoc -http=:6060` в разделе `internal/handlers`.
